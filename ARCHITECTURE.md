> Status: **proposal produced at Step 1 (audit only)**. No application code exists yet.
> Naming (confirmed by the owner): the application is **GuitarRiff**. The Python package is `guitarriff`.
> Older prompts that say `FreeTabGen` refer to the same project.
>
> **Decisions after Step 1 (they supersede anything below that contradicts them):**
> - **No audio is downloaded from YouTube.** Every mention below of yt-dlp, "download" or "YouTube download service" is obsolete. The YouTube link is only used to work with the song; how the audio needed by Basic Pitch is obtained is an open question (`PROJECT_STATUS.md`, Q1).
> - Frontend: the owner delegated the choice; Vite + React + TypeScript is kept.
> - Instruments: they will be defined by the following prompts; guitar tunings remain the default design target.

### 1.3 Critical finding: Basic Pitch vs Python 3.12

Verified by inspecting the `basic-pitch 0.4.0` wheel metadata and by trying to resolve its dependency:

- On Linux with Python >= 3.11, `basic-pitch 0.4.0` depends on `tensorflow>=2.4.1,<2.15.1`.
- On Python 3.12, pip cannot find any TensorFlow release matching that range. The only versions offered start at 2.16.0rc0.
- **Consequence:** `pip install basic-pitch` with its default backend **fails on Python 3.12**.

Decision proposed:

1. **Pin the project to Python 3.11** (`.python-version`, `requires-python = ">=3.11,<3.12"`), installed through `uv`. TensorFlow 2.15 supports 3.11.
2. Keep an alternative to evaluate in Step 3 only if TensorFlow proves too heavy: the ONNX backend of Basic Pitch (`onnxruntime`) on Python 3.11. Not validated yet; do not assume it works.

## 2. Architectural principles

1. **One-way pipeline.** Each stage consumes the output of the previous one and produces a well-defined, serializable artifact.
2. **Basic Pitch is isolated.** Exactly one module (`transcription/basic_pitch_adapter.py`) may import `basic_pitch`. Everything else depends on the `Transcriber` interface and on `NoteEvent`. A test enforces this (Step 8).
3. **librosa is a helper, not a transcriber.** It is used for preprocessing and analysis only (resampling, harmonic/percussive separation, tempo/beat estimation). It is never presented or wired as an equivalent replacement for Basic Pitch.
4. **`NoteEvent` is the single contract** between transcription and everything downstream (mapping, tab, chords, MIDI, frontend).
5. **Pure functions where possible.** Mapping, tab generation, chord detection take data in and return data out, with no I/O, so they are testable without audio.
6. **No network in tests.** yt-dlp and Basic Pitch are mocked/faked at their boundary in unit tests; real runs are marked `slow`/`integration`.
7. **Input abstraction.** A job accepts either a YouTube URL or an uploaded audio file. Upload is implemented first (Step 5) because it is legally and technically safer.

## 5. Module responsibilities

| Module | Responsibility | Must NOT |
|---|---|---|
| `models` | Data contracts, validation, serialization | Contain logic touching files or network |
| `ingest` | Obtain audio bytes from a source; enforce size/duration limits | Decode or transcribe audio |
| `audio` | Decode with FFmpeg, normalize to mono WAV, optional cleanup | Detect notes |
| `transcription` | Turn a WAV file into `NoteEvent`s through the `Transcriber` interface | Leak Basic Pitch types outside the adapter |
| `postprocess` | Clean events; estimate tempo/beats; quantize | Choose strings/frets |
| `instruments` | Tunings, capo, playable range, candidate positions per pitch | Decide the final fingering |
| `tabgen` | Pick the best fret/string per note (minimize hand movement) | Read audio |
| `chords` | Group simultaneous/near notes and name the chord | Modify note events |
| `export` | Serialize to MIDI, ASCII tab, MusicXML | Recompute analysis |
| `pipeline` | Chain stages in order, report progress, map errors to codes | Contain domain logic of any stage |
| `jobs` | Persist job state, run jobs one at a time | Know about HTTP |
| `api` | HTTP contract, validation, status codes | Contain pipeline logic |
| `frontend` | Submit jobs, poll status, render tab/chords, play back | Reimplement analysis |

## 6. Normalized `NoteEvent` data model

### 6.1 `NoteEvent` (core, immutable)

| Field | Type | Constraints | Notes |
|---|---|---|---|
| `id` | int | >= 0, unique per transcription, ordered by `start` then `pitch` | Stable reference used by tab/chords |
| `pitch` | int | 0–127 (MIDI note number) | 60 = C4 |
| `start` | float | >= 0, seconds | Onset time |
| `end` | float | > `start`, seconds | Offset time |
| `velocity` | int | 1–127 | Basic Pitch amplitude (0–1) scaled to MIDI range |
| `confidence` | float or null | 0–1 | Model-derived strength; null if unavailable |
| `pitch_bends` | list of `(t, semitones)` or null | `t` relative to `start` | Optional; unused by MVP |
| `source` | string enum | `basic_pitch` for now | Keeps room for other transcribers |

Derived read-only property: `duration = end - start`.

### 6.2 `Transcription` (container)

| Field | Type | Notes |
|---|---|---|
| `events` | list[NoteEvent] | Sorted by `start`, then `pitch` |
| `audio_duration` | float | Seconds |
| `sample_rate` | int | Of the audio actually transcribed |
| `model` | object | `{name, version}` for traceability |
| `tempo_bpm` | float or null | Filled by `postprocess/rhythm` |
| `beats` | list[float] or null | Beat times in seconds |

### 6.3 Downstream models (reference `NoteEvent.id`, never copy pitch)

- `FretPosition { string: int (1 = highest string), fret: int (0..max_fret) }`
- `TabNote { note_id: int, position: FretPosition, technique: null }`
- `Tablature { tuning, capo, max_fret, notes: list[TabNote], cost: float }`
- `ChordEvent { start, end, name, root, quality, note_ids: list[int], confidence }`

### 6.4 Validation rules (enforced by Pydantic, tested in Step 4)

- `end > start`, `start >= 0`
- `pitch` in 0–127, `velocity` in 1–127, `confidence` in 0–1 when set
- events sorted, ids unique
- round-trip JSON serialization is lossless

### 6.5 Example

```json
{
  "events": [
    {"id": 0, "pitch": 64, "start": 0.52, "end": 0.91, "velocity": 88,
     "confidence": 0.83, "pitch_bends": null, "source": "basic_pitch"}
  ],
  "audio_duration": 30.0,
  "sample_rate": 22050,
  "model": {"name": "basic-pitch", "version": "0.4.0"},
  "tempo_bpm": 96.0,
  "beats": [0.5, 1.125, 1.75]
}
```

## 7. Processing pipeline

```
YouTube URL ─┐
             ├─► [1 ingest] ─► raw media file
Upload file ─┘
                  │
                  ▼
            [2 audio.ffmpeg]   decode -> mono WAV, fixed sample rate
                  │
                  ▼
            [3 audio.preprocess]  trim silence, loudness, optional HPSS (librosa)
                  │
                  ▼
            [4 transcription]  Basic Pitch (isolated adapter) -> Transcription
                  │
                  ▼
            [5 postprocess]    cleanup, tempo/beats, quantization
                  │
                  ├──────────────► [6a export.midi]   MIDI file
                  ▼
            [6 instruments]    candidate (string, fret) for each pitch
                  │
                  ▼
            [7 tabgen]         optimal fingering -> Tablature
                  │
                  ├──► [8 chords] ChordEvent list
                  ▼
            [9 export + result JSON]  MIDI, ASCII tab, MusicXML, result.json
                  │
                  ▼
            frontend (tab view, chord bar, playback)
```

| Stage | Input | Output artifact | Progress weight (initial guess) |
|---|---|---|---|
| ingest | URL or upload | `source.<ext>` | 15% |
| ffmpeg | source file | `audio.wav` | 5% |
| preprocess | `audio.wav` | `audio_clean.wav` | 5% |
| transcription | `audio_clean.wav` | `transcription.json` | 45% |
| postprocess | `transcription.json` | `notes.json` | 5% |
| instrument mapping + tabgen | `notes.json` | `tab.json` | 10% |
| chords | `notes.json` | `chords.json` | 5% |
| export | all of the above | `song.mid`, `tab.txt`, `song.musicxml`, `result.json` | 10% |

Job status values: `queued`, `downloading`, `preprocessing`, `transcribing`, `analyzing`, `mapping`, `exporting`, `done`, `failed`, `cancelled`.

Default limits (configurable, to be validated in Step 19): max duration 10 min, max upload 50 MB, one job at a time.

## 8. API structure (REST, prefix `/api/v1`)

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | Liveness + tool versions (ffmpeg, model loaded) |
| GET | `/instruments` | Tuning presets (standard, drop D, …) |
| POST | `/jobs` | Create a job from JSON `{ source: {type: "youtube", url}, options }` |
| POST | `/jobs/upload` | Create a job from multipart audio file + options |
| GET | `/jobs/{id}` | Status, stage, progress 0–1, error if any |
| GET | `/jobs/{id}/result` | Full result JSON (notes, tab, chords, tempo) |
| GET | `/jobs/{id}/artifacts/{name}` | `midi`, `audio`, `tab.txt`, `musicxml` |
| DELETE | `/jobs/{id}` | Cancel and delete artifacts |

`options`: `{ instrument: "guitar", tuning: "standard", capo: 0, max_fret: 22 }`.

Error format (all endpoints): `{ "error": { "code": "VIDEO_TOO_LONG", "message": "...", "details": {} } }`.
Codes are defined in `errors.py`; examples: `INVALID_URL`, `DOWNLOAD_FAILED`, `VIDEO_TOO_LONG`, `UNSUPPORTED_AUDIO`, `TRANSCRIPTION_FAILED`, `JOB_NOT_FOUND`.

Status delivery: client polling in the MVP. Server-sent events may be added later without changing the resource model.

## 9. Testing strategy

| Level | Scope | Tooling | Network/model |
|---|---|---|---|
| Unit | models, cleanup, mapping, tabgen, chords, export | pytest | none |
| Contract | `Transcriber` interface honored by a fake and by the Basic Pitch adapter | pytest | fake only |
| Architecture | only `basic_pitch_adapter.py` imports `basic_pitch`; only `youtube.py` imports `yt_dlp` | pytest scanning imports | none |
| Integration (slow) | real Basic Pitch on tiny **synthetic** WAVs (sine/plucked tones generated with numpy) | pytest `-m slow` | model local |
| API | FastAPI `TestClient` with faked pipeline stages | pytest | none |
| Frontend | components and API client | Vitest | mocked API |
| E2E | upload -> tab displayed | Playwright | real backend, fake or tiny model input |

Rules:

- Fixtures are generated in code (known notes, known timings) so expected `NoteEvent`s are exact and no copyrighted audio is stored.
- Transcription accuracy is checked with tolerances (pitch exact, onset within tens of ms), never exact float equality.
- CI runs unit, contract, architecture and API tests; slow tests run on demand.
- A step is not done until its tests pass and the result is recorded in `PROJECT_STATUS.md`.

## 10. Technical risks and limitations

| # | Risk | Severity | Mitigation |
|---|---|---|---|
| R1 | Basic Pitch does not install on Python 3.12 (verified) | High | Pin Python 3.11 via `uv`; Docker image; evaluate ONNX backend only if needed |
| R2 | TensorFlow is heavy (install size, RAM, cold start) | Medium | Lazy singleton model load; concurrency 1; document minimum RAM |
| R3 | YouTube download fragility: yt-dlp breaks when YouTube changes | High | Wrap behind interface, pin + regularly update, clear `DOWNLOAD_FAILED` error, upload fallback |
| R4 | Legal/ToS: downloading YouTube audio may violate YouTube's Terms and copyright | High | Decision required from the owner (personal/local use only vs public service); upload path implemented first; no redistribution of audio |
| R5 | Polyphonic transcription is imperfect: wrong or missing notes, octave errors, especially with vocals, drums, distortion | High | Optional HPSS preprocessing, confidence filter, manual correction UI (Step 18), honest UI wording |
| R6 | Tab generation is ambiguous: many (string, fret) choices per pitch | Medium | Cost-based optimization (hand span, position shifts); configurable tuning/capo/max fret |
| R7 | Tempo/beat estimation errors break quantization and bar lines | Medium | Allow manual tempo override; keep unquantized events available |
| R8 | Chord detection on noisy note sets gives false names | Medium | Report confidence; show chords as suggestions |
| R9 | Long inputs cause timeouts/memory exhaustion | Medium | Duration/size limits, cancelation, cleanup of `data/` |
| R10 | Sandbox: 1 core, ~4 GB RAM slows real-model tests | Low | Keep real-model tests tiny and marked `slow` |
| R11 | Security: URL injection, huge uploads, path traversal | Medium | Strict URL allow-list (YouTube hosts), size limits, sanitized filenames, jobs isolated by UUID directory |
| R12 | Naming inconsistency (GuitarRiff vs FreeTabGen) | Low | Owner to confirm |

Known scope limits of the MVP: guitar first (bass/ukulele are tuning presets later), no techniques (bends, slides, hammer-ons), no lyrics, no stem separation of vocals/drums.
